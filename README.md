# yassermansour.com

My personal site. Plain HTML and CSS, generated by a short Node script from
one file of project data. No framework and no runtime dependencies.

The 2026 redesign adds individual product chapters, Understand, the Mansour
Technologies founder story and an expanded About page. See
[the redesign and verification report](docs/REDESIGN.md), including the company
HTTPS issue to resolve before publication.

## Working on it

Requires Node 20 or newer.

```bash
npm run dev     # builds, serves http://localhost:4321, rebuilds on change
npm test        # builds, then checks links, images, metadata and the sitemap
npm run build   # writes the site to dist/
```

## Layout

```
src/
  projects.js     every project, in display order — edit this to change the work
  site.js         name, email, links used on more than one page
  styles.css      the whole design: tokens first, then layout, then pages
  layout.js       <head>, header and footer
  components.js   small pieces shared by pages (facts list, screenshot)
  html.js         escaping template tag
  pages/          one module per page type
  main.js         progressive enhancements: clock, copy email, learning illustration
  learning-demo.js labeled interactive illustration shared with the Understand page
public/           copied to dist/ as-is (fonts, images, icons, CNAME)
scripts/
  build.mjs       renders pages, writes sitemap.xml and robots.txt
  serve.mjs       local server that behaves like GitHub Pages
  check.mjs       fails on broken links, missing alt text, bad metadata
  og.html         source for public/og.png
  browser-qa.html real-browser viewport matrix; copy temporarily into dist/ to run
```

The major homepage chapters are art-directed in `src/pages/home.js`; case studies
are generated from `src/projects.js`. Keep Understand’s planned-launch wording
in the homepage, About and project data in sync after confirming its actual launch.

Adding a project means adding an entry to `src/projects.js`. With
`featured: true` it gets a case study at `/work/<slug>/` and joins the case-study
navigation. Add an intentional chapter in `src/pages/home.js` when featuring it
on the homepage. Without `featured`, it appears under earlier explorations.

## Deploying

`.github/workflows/pages.yml` builds and publishes `dist/` on every push to
`main`, once the repository's GitHub Pages source is switched from "Deploy
from a branch" to "GitHub Actions". Make that switch in the same step as the
merge: with the old setting, GitHub would serve the repository root, which no
longer contains a site.
